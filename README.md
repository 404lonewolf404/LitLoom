# LitLoom · 研究生论文工作台

> 项目仓库：[404lonewolf404/LitLoom](https://github.com/404lonewolf404/LitLoom) · 作者 / 维护者：[@404lonewolf404](https://github.com/404lonewolf404)

本项目是一个**本地优先、可持续积累的个人研究文献工作台**。把论文发现、阅读分诊、笔记、证据和来源记录放进同一个可导出/备份的资料库，按多年连续使用设计。平台将重复检索、去重、分页全文查询、阅读历史、自动追踪和运行维护交给系统，研究者保留最终判断权。

工程架构、数据边界、Agent 能力和发布门槛见 [`ARCHITECTURE.md`](ARCHITECTURE.md)；开发、测试和发布流程见 [`DEVELOPMENT.md`](DEVELOPMENT.md)；HTTP 契约见 [`openapi.yaml`](openapi.yaml)。

LitLoom 还提供可选的无依赖 MCP stdio 适配器，可让外部 Agent 调用论文检索、历史查询、逐页证据读取和持久化 AI 分析任务。网页端内部使用 LangChain 工具适配和 LangGraph 决策循环；自主 Agent 的每一步会写入 PostgreSQL 的运行、步骤、工具调用和产物记录，刷新后仍可追踪。

## 快速启动（Windows）

需要 Python 3.10+ 和 PostgreSQL 17。首次在新环境运行前安装项目依赖（包含 FastAPI、PostgreSQL 驱动和 LangGraph Agent）：

```powershell
python -m pip install -e .
Copy-Item .env.example .env
```

首次配置时编辑 `.env`，填写 PostgreSQL 连接地址 `LITLOOM_DATABASE_URL`。例如：

```text
LITLOOM_DATABASE_URL=postgresql+psycopg://用户名:密码@127.0.0.1:5432/litloom
```

请先确保 PostgreSQL 服务和 `litloom` 数据库可用。模型配置可以稍后在应用设置页完成；`.env` 保存本机配置，**不要提交到 GitHub**。

```powershell
python .\app.py
```

应用从项目根目录 `.env` 读取 `LITLOOM_DATABASE_URL`，并可按 `LITLOOM_POSTGRES_DATA_DIR` / `LITLOOM_POSTGRES_BIN_DIR` 自动启动本机 PostgreSQL。打开控制台显示的本机地址（默认 <http://127.0.0.1:8765>）。应用仅绑定本机回环地址，不会开放给局域网。停止服务按 `Ctrl+C`。也可运行 `.\run.ps1`。

如需在同一台机器上区分团队成员，可在 `.env` 中设置 `LITLOOM_AUTH_MODE=team` 后重启。首次启动时，在页面输入 `<LITERATURE_DATA_DIR>/bootstrap-admin-token.txt` 中的一次性令牌创建所有者；随后由管理员在“设置 → 团队成员”创建账号。PostgreSQL 运行版当前采用共享工作区；工作区独立数据库隔离尚未实现，`LITLOOM_TENANT_MODE=isolated` 会被拒绝。服务仍只监听本机回环地址。

需要作为可安装命令运行时，可在项目目录执行 `python -m pip install -e .`，之后使用 `litloom` 启动。PowerShell 启动脚本支持自定义端口和资料目录，示例：`.\run.ps1 -Port 8876 -DataDir D:\ResearchData`。

PostgreSQL 保存论文、阅读卡、检索历史和任务等业务数据；PDF 与备份仍存放在 `LITERATURE_DATA_DIR` 指定的本地目录（默认项目目录下的 `data/`）。可在启动前把 `LITERATURE_DATA_DIR` 改到 OneDrive 外的自选目录，或设置 `LITERATURE_PORT` 更换端口。LitLoom 运行必须提供 `LITLOOM_DATABASE_URL`，连接不上 PostgreSQL 时会明确停止，不会悄悄切到 SQLite。旧 SQLite 文件不参与启动或自动迁移；本机遗留文件已从项目数据目录移到 `%LOCALAPPDATA%\LitLoom\legacy-sqlite\` 留档。请勿把 `.env`、`data/` 或备份加入公开 Git 仓库。

**数据库状态：**运行时仅使用 PostgreSQL；SQLAlchemy 2.x Engine / QueuePool 负责连接、事务和查询执行，psycopg 3 是 PostgreSQL 驱动，schema 由 Alembic 版本化管理，全文检索使用 PostgreSQL `pg_trgm` 索引。连接池按需创建，最大连接数默认为 12，可通过 `LITLOOM_DB_POOL_MAX` 和 `LITLOOM_DB_POOL_TIMEOUT` 调整。复杂检索保留显式 SQL；ORM 只在能简化实体 CRUD 时引入。SQLite 不参与应用运行；仅保留显式迁移脚本和隔离测试适配器。旧 SQLite 文件位于 `%LOCALAPPDATA%\LitLoom\legacy-sqlite\`，不会自动读入数据库。

PDF 逐页文本提取是可选能力：需要时安装 `pypdf`（`python -m pip install pypdf`）。要让 AI 精读识别公式、图片、表格和流程图，建议同时安装 `PyMuPDF`（`python -m pip install PyMuPDF`）；页面会按需渲染为本地缓存，不修改原 PDF。

安装全部 PDF 能力也可以使用 `python -m pip install -e ".[pdf,vision]"`。视觉模型需支持 OpenAI Chat Completions 的 `image_url` 内容块；纯文本模型会自动降级为文字精读并在结果中显示降级记录。

## 当前可用能力

- 今日页显示馆藏、待读、正在读、追踪主题和最近同步结果。
- 今日页提供本地研究简报：汇总时间窗口内新增论文、主题变化、阅读积压和异常同步。下一步推荐会并行采用 OpenAlex 已计算的 related works 与 Semantic Scholar hosted recommendations 信号：一部分用于已有馆藏候选排序，一部分把两家服务的外部候选统一展示，保留来源并由你确认加入；再结合本地主题与用户反馈。外部推荐异步刷新并缓存，单个服务不可用时保留其他信号并降级到本地结果，不依赖模型。
- 数据分析页显示近 30 天新增/读完、积压、来源成功率、去重率、反馈样本和 12 周趋势，用于调整检索频率和阅读计划。
- 数据分析页的“开发优化闭环”会展示原始抓取→过滤→候选→新增漏斗，并依据 Precision 样本、反馈覆盖、去重率、来源失败率和 p95 自动生成 P1/P2/P3 优化动作，支持长期持续的检索质量复盘。
- 检索漏斗的来源级详情从 schema 7 起单独持久化；schema 8 增加结构化阅读卡。旧运行如果只有来源名称会明确显示“历史详情缺失”，不会把未知数量伪装成零，也不会污染后续长期基线。
- 运维指标页内置反馈覆盖率、平均同步耗时、审计事件数和数据库 schema 版本；`/api/health`、`/api/ready` 与 `/api/audit` 可供本地进程管理和问题定位使用。每条结构化请求日志带有请求 ID、客户端和 `duration_ms`，便于定位慢请求。
- 数据分析页与 `/api/evaluation` 会基于明确的“相关/忽略”反馈计算 Precision@5、Precision@10 和样本状态，作为调整检索扩展、排序权重和来源策略的可复现实验基线。
- 项目还提供零依赖离线回归评测：`python .\scripts\evaluate_retrieval.py` 读取 `evaluation/retrieval_baseline.json`，计算 Precision@k、Recall@k 和 MRR；把其中的稳定候选 ID 换成自己的人工标注集即可比较连接器、排序或提示版本，未标注案例不会被当作负例。
- `/api/diagnostics` 包含版本、schema、质量门和可选灰度分桶信息。默认稳定通道不改变行为；只有显式设置 `LITLOOM_CANARY_FEATURES`、百分比和盐值后，指定 workspace 会稳定地进入实验分组，便于逐步发布排序或模型路由变更。
- 系统设置页集中展示 OpenAI 兼容模型连接、数据库 schema、调度器、API 延迟和错误率；`/api/metrics` 还提供模型任务级调用量、失败率、p50/p95 延迟、提供方返回的 token 与费用统计。遥测仅保留模型 ID 和服务主机，按日汇总长期指标，并将最近调用明细限制为 10,000 条；不记录 prompt、回复正文、图片、密钥或完整请求地址。提供方未返回费用时显示未知，不按假设价格估算。`/api/diagnostics` 额外返回版本、连接器边界、数据完整度、反馈覆盖率和 SLO 门槛。
- 手动建立论文记录；通过 **arXiv Atom API**、**OpenAlex Works API**、**Crossref REST API**、**Europe PMC REST API** 与可选 **DBLP API / OpenReview API** 检索来源。普通发现搜索和手动运行已保存主题都会先保存为候选，不会自动进入文献库；发现页可先看 AI 相关性建议或人工复核，再逐篇/批量明确加入。周期订阅仍保留后台自动追踪策略。检索会保留原始问题，并对常见中英文研究概念自动生成别名/写法变体，多路召回后按 DOI、arXiv ID、规范题名、近题名和年份合并。
- 检索计划会识别对象、方法、任务、评价等研究维度；精准/平衡/深度三档分别控制召回成本，深度模式额外补充综述、基准、数据集评测、失败分析和前沿入口。结果采用来源加权 Reciprocal Rank Fusion，再用可解释的词项相关度、前沿度、长期新颖性和 MMR 多样性重排，显示高相关、邻近方向和跨领域线索；已读/收藏论文中的新术语可用于相邻表达扩展。每次运行显示每条召回层、命中的概念路径和跨源去重结果。
- 发现页的“AI 工具检索”使用标准 function calling：模型先拆解自然语言研究问题，再并行选择学术来源和已配置的 Tavily / DeepSeek Search。联网来源只负责拓宽网页召回，LitLoom 会用 DOI、arXiv、Crossref 或 OpenAlex 核验身份；未核验网页明确标记为“仅线索”，不会冒充正式论文。DeepSeek Fetch 可由 Agent / MCP 将指定公开网页读取为 Markdown。真实候选及来源会交回模型进行相关性筛选。调用轮数和结果规模有上限，重复论文按研究意图排除；模型只筛选工具返回的候选，不生成或补写论文元数据。
- 每次候选搜索都会进入可恢复的历史记录，可按问题检索、恢复旧候选或按原条件重搜；AI 只看研究问题与最多 40 篇候选的题名/摘要等元数据，不读取 PDF 全文也不负责导入。你的“相关/不相关/跳过”决定按研究意图保留，后续同方向检索会沿用判断、降低重复干扰；可以撤销，且更换研究问题不会串用旧反馈。
- 发现页支持作者/期刊或会议/年份/文献类型过滤、排除词，并按综合相关性、最新、新发现、经典/高影响或邻域探索排序；排序同时参考标题短语、摘要概念覆盖、来源交叉确认、开放获取线索、引用量和个人反馈。可选沿本地馆藏论文标题搜索相似、引用与后续工作，且相关度评分与召回使用同一套中英文概念桥接。可选择只保留当前主题未出现过的论文，适合多年持续追踪。
- 用规范 DOI、去版本号的 arXiv ID 和“规范题名 + 年份”做保守去重；新增来源不会覆盖已有笔记、阅读状态和主题。
- 文献库支持关键词筛选、研究主题/阅读状态、收藏与 BibTeX / JSON 导出；JSON 导出和导入包含主题匹配、引用线索、反馈、AI 分析版本、候选搜索历史/筛选状态/跨次反馈与审计事件，重复导入会跳过已保存的相同 AI 版本，便于长期迁移与分析。完整备份额外包含 PDF 附件。
- 文献库提供服务器端分页和 PostgreSQL `pg_trgm` 全文/子串检索，可查询标题、作者、摘要、主题、标签、个人笔记、结构化阅读卡以及已提取 PDF 原文；搜索结果返回匹配字段和片段，支持收藏、年份、有阅读卡和稳定排序过滤。派生检索索引可重建。
- 文献库支持最多 500 篇的事务级批量分诊：全选当前筛选结果后可批量加入待读、标记已读、排除、收藏或设置研究主题；每篇论文显示结构化阅读卡完成度。
- 导入 BibTeX、RIS 和 JSON；支持从论文记录中的公开 `pdf_url` 自动下载 PDF，也可手动关联本地 PDF（最多 100 MB/篇，按 SHA-256 内容寻址保存），重复下载会自动复用已有附件；可选提取逐页文本并按页码检索。
- 论文页内检索支持可选的 Embedding 语义索引：将已提取的 PDF 纯文本分块、异步保存页码/文本哈希/原文偏移，并与关键词检索融合排序，适合查同义表达和跨语言概念。任务有持久进度、取消、失败后可重试和重启续跑；文本变更后只重建受影响页面。未配置或请求失败时自动回退关键词检索。建立索引前会要求本次外发授权，只发送文本，不调用图像识别。
- 阅读台可管理待读/在读/已读、主题和自己的阅读笔记，并维护结构化阅读卡：研究问题、贡献、方法、数据集、基线、结果、局限、可复现性、证据定位、个人启发和下一步行动。
- 论文详情提供**快速全文阅读卡**和**多模态 AI 深度精读**：快速阅读卡从本地逐页 PDF 文本中优先选择摘要、方法、数据集、实验、结果和局限等重点页，避免把整篇长文重复发送给模型；不渲染或发送页面图片，并优先用本地原文生成可核验引文，只有 OCR 过于破碎时才追加一次模型定位。多模态深度精读会分析抽样页面中的公式、图表和算法，并额外输出问题形式化、算法步骤、公式变量解释、结果表格和批判性分析。结论保留附件/页码锚点，文字引文会与本机完整原文核对；深度精读会显示视觉抽样边界。模型不支持视觉输入时自动降级并记录原因。点击生成阅读卡后会**自动填充当前为空的结构化字段**并建立历史版本，已有人工记录始终保留；API 传 `apply:false` 或历史分析页面仍可只生成草稿。
- “读前知识”会从成功的阅读卡与精读中自动归档本文先修概念、专业术语和公式符号，区分论文明确依赖、背景释义与 AI 建议；能回到原文的位置保留页码和短引文。可跨论文检索、按类型/掌握状态筛选、记录自己的解释并标记待学/学习中/已掌握；到期复习可自评“忘了/困难/记住/轻松”，按记忆表现安排下次复习。复习计划本地计算并随 JSON 导出与 ZIP 备份保存，不会额外调用模型。
- 全文 AI 任务会按本地 PDF 内容、模板、语言和流水线版本做可复用缓存：刷新页面、重新打开论文或重复点击不会为未变化的全文再次发起模型请求；替换 PDF、重新提取页面或切换模型后才会重新分析。快速阅读卡默认最多发送 36,000 字符的重点页文本，完整 PDF 仍留在本地做页码和引文核验；公式、图表和图片识别由多模态深度精读完成。深度精读默认使用 18,000 字内容块、每块最多 2 张视觉页。独立全文任务默认最多同时运行 2 个，任务内部模型请求最多并发 4 个，PDF 渲染最多并发 1 个；视觉图片默认按 120 DPI/自动细节压缩，避免长论文造成内存峰值。分块证据抽取和深读汇总默认关闭额外 reasoning 链，只输出结构化 JSON；可用 `LIT_AGENT_ANALYSIS_REASONING_EFFORT` 恢复低/中/高 reasoning。可用 `LIT_AGENT_MODEL_CONCURRENCY`、`LIT_AGENT_AI_JOB_CONCURRENCY`、`LIT_AGENT_FULLTEXT_CHUNK_CHARS`、`LIT_AGENT_READING_CARD_CONTEXT_CHARS`、`LIT_AGENT_DEEP_READ_VISUAL_PAGES_PER_CHUNK`、`LIT_AGENT_VISUAL_DPI` 调整。默认不发送应用层 JSON 输出上限；可用 `LIT_AGENT_MAX_OUTPUT_TOKENS` 及各阶段变量设置正数保护，设为 `0` 表示不限制。
- 模型请求默认使用 OpenAI 兼容的流式响应，长输出期间会持续接收数据，降低中转网关因长时间无响应返回 524 的概率；若某个兼容服务不接受 `stream`，程序会自动重试一次非流式请求，也可设置 `LIT_AGENT_STREAM=0`。
- 笔记与结构化阅读卡每次保存都会形成历史快照，可查看来源和时间并恢复旧版本；历史随 JSON 导入导出和完整 ZIP 备份保存。
- 自动追踪页可以打开单次运行详情，查看每个来源的抓取、过滤、候选、新增、重复和查询变体命中；数据分析页会显示阅读卡覆盖率与字段完成率。
- 可保存定时检索主题；调度记录持久化在 PostgreSQL 中。服务启动后会补跑到期主题；断网/限流会显示失败来源，并安排重试。
- 每次同步都有持久化 job 状态、当前阶段、尝试次数、错误和下次重试时间；服务重启会把未完成 job 标记为 interrupted，维护页可查看索引完整度和孤儿附件/页文本。
- 创建完整备份，包含 PostgreSQL 一致性 dump、PDF、manifest 和 SHA-256；恢复前校验数据库/附件并先留一份当前数据库安全副本。
- 应用运行期间默认每天自动创建一次完整 ZIP 归档，系统设置可调整间隔和自动归档保留数量；自动归档失败会记录原因并在较短间隔重试，手动创建的长期归档不会被自动轮换删除。设置 `LITERATURE_AUTO_BACKUP_HOURS=0` 可关闭默认策略，`LITERATURE_BACKUP_RETENTION` 可设置默认保留数。
- 可选连接任意 OpenAI 格式兼容模型，提供摘要级快速助读和全文阅读卡/多模态精读。配置中心支持中转、本地服务和自建网关：`Base URL` 与 `API 请求地址` 至少填写一个；前者是服务根地址，后者是完整 POST 端点且优先原样调用，因此不绑定任何供应商域名或固定路径。支持 Chat Completions 与 Responses，使用 `Authorization: Bearer`。页面测试直接验证真实推理接口，服务不必提供 `/models`。快速阅读卡只发送逐页文本；全文深度精读在你点击分析并勾选同意后才发送单篇论文的逐页文本和按需渲染的页面图像，不发送个人笔记；请在模型服务商处选择支持视觉输入的模型。视觉页缓存可以通过 `/api/papers/{id}/visual-pages` 查看，结果保留模型、提示版本、文字/视觉输入哈希、页码和降级记录，AI 阅读卡默认只填充空字段、不覆盖人工内容。
- 发现结果会按可解释规则分为高相关、邻近方向、低相关和待核验，并显示命中理由；保存的主题会记住每篇论文首次/最近出现、出现次数和你的“相关/忽略”决定。
- 主题反馈会抑制已经忽略的重复推荐，但同一篇论文仍可在另一个主题中出现；论文详情可按 DOI 同步 OpenAlex 参考文献线索并扩展引用/被引/相似论文，引用关系与相关性、论文质量分开保存。
- 关键写操作、同步、反馈和备份会写入不含密钥的审计事件；请求响应带 `X-Request-ID`，便于把页面报错与本地日志对应起来。

## OpenAI 兼容模型配置

不配置模型时，检索、去重、笔记、导入导出、数据分析和自动追踪仍可用。打开页面的“自动追踪 → 模型配置”或“数据分析 → 模型配置”，填写 OpenAI 兼容格式：

- `Provider`: 任意名称（仅用于识别）
- `Base URL`: 可选，服务根地址，例如 `https://relay.example.com/v1`
- `API 请求地址`: 可选，完整的 POST 推理地址，例如 `https://relay.example.com/v1/chat/completions`；填写后优先原样使用
- `Model`: 例如 `gpt-4.1-mini`
- `任务模型路由（可选）`: 可分别指定快速任务、论文分析和多模态视觉的模型 ID；三者共用当前端点与 API Key，留空时使用主模型。快速模型用于检索规划、AI 初筛、摘要助读和元数据整理；分析模型用于全文阅读与证据综合；视觉模型只用于明确授权的视觉分析。
- `Embedding 模型 ID（可选）`: 需要服务商单独支持 OpenAI 兼容 `/embeddings`；它可能与生成模型不同。API 地址可留空并按 `Base URL/embeddings` 推导，也可填写完整自定义端点。
- `Temperature`: `0` 到 `2`
- `API Key`: 默认保存到本地数据目录的 `model-secret.json`，不写入 PostgreSQL、备份或日志；也可改用环境变量或 `LIT_AGENT_API_KEY_FILE` 指定的 JSON/纯文本密钥文件

Embedding 只在你显式建立论文语义索引或勾选“语义 + BM25”检索时调用；使用同一个 API Key，按所选服务的规则计费。普通 BM25、PDF 文本提取和图片精读不依赖 Embedding 配置。

配置窗口提供 DeepSeek 快速预设：它会填入官方 OpenAI 兼容入口 `https://api.deepseek.com/chat/completions`、Chat Completions 协议和当前文档中的模型提示（`deepseek-flash`、`deepseek-v4-pro`），同时保留常见兼容模型名 `deepseek-chat`、`deepseek-reasoner` 供手动选择。预设内容仍可编辑，API Key 必须由你单独填写；切换供应商时程序会要求新 Key，避免误用上一家服务的密钥。参数依据 [DeepSeek 官方 API 文档](https://api-docs.deepseek.com/quick_start)。

兼容服务的非本机地址必须使用 HTTPS。Chat Completions 服务使用 OpenAI 的 `messages` 请求体，Responses 服务使用 `input` 请求体；保存后点击“快速连通”优先检查 `/models`，点击“首 token 实测”会发送单 token 的流式请求，收到模型首段文字就结束，不等待完整答案，并显示首 token 与总耗时。普通摘要/精读请求默认带 `reasoning_effort=low`（Responses 使用 `reasoning.effort`），避免供应商自行选择高推理档；可用 `LIT_AGENT_REASONING_EFFORT` 调整，网关不支持时会自动移除兼容字段重试。也可以在启动 PowerShell 中设置密钥，勿把密钥写进源码或数据库：

```powershell
$env:LIT_AGENT_API_KEY = "你的服务密钥"
$env:LIT_AGENT_MODEL = "服务支持的模型名"
$env:LIT_AGENT_BASE_URL = "https://relay.example.com/v1"
# 或直接指定完整端点（指定后优先使用）
# $env:LIT_AGENT_API_URL = "https://relay.example.com/v1/chat/completions"
python .\app.py
```

使用兼容服务时替换模型名和服务地址。程序启动时会自动读取项目根目录 `.env`，且不会覆盖系统环境变量；也可用 `LITERATURE_ENV_FILE` 指定其他文件。摘要助读只发送题名、作者、年份、venue 与摘要；快速阅读卡只在论文详情中单独勾选同意并启动后发送该论文逐页 PDF 文本，深度精读还会发送按需渲染的页面图像。**个人笔记不会发送**。视觉分析需要支持 OpenAI 兼容图像输入的模型；请先检查模型服务商的数据政策。设置页会显示密钥来源，服务更新或重启后会自动读取本地密钥文件。

学术索引可选 Key 使用项目根目录 `.env` 中的 `LIT_OPENALEX_API_KEY` 和 `LIT_SEMANTIC_SCHOLAR_API_KEY`。LitLoom 仅将 OpenAlex Key 放入 OpenAlex 请求，将 Semantic Scholar Key 放入其 `x-api-key` 请求头；未配置时仍尝试公开配额并按来源限流策略降级。Key 不进入数据库、搜索历史或诊断接口。联网发现可选 Tavily 使用 `LIT_TAVILY_API_KEY_FILE` 指向的本地密钥文件。

## 数据与研究质量说明

- arXiv 论文常为尚未同行评审的预印本；OpenAlex 与 Crossref 结果也需核对正式出版页面。
- 学术元数据接口覆盖并不完全相同；“没有检索到”不等于“没有相关论文”。Google Scholar 没有公开通用检索 API，本项目不依赖页面抓取。
- 当前去重优先处理 DOI、arXiv ID 和规范题名/年份，并对无强标识的近题名做高阈值合并；不会擅自将带不同强标识的预印本与正式版合并。复杂版本关系、撤稿状态和模糊匹配复核仍是后续能力。
- 当前 PDF 文本提取使用可选 `pypdf`/`PyPDF2`，视觉渲染使用可选 `PyMuPDF`；系统会报告空页/低质量页并保存文本和视觉输入哈希。扫描版没有文字层时可以交给视觉模型做页面级分析，但不会生成无法核验的文本引文；公式、图表数字和复杂 OCR 仍需回到 PDF 原页复核，AI 不替代研究者判断论证是否充分。
- 当前自动监测在应用运行期间按周期执行，错过的计划会在下次启动后补跑；关机期间不会后台运行，也暂未发送邮件/手机通知。
- 自动备份同样只在应用运行期间执行；建议把 `data/backups/` 定期复制到另一块磁盘或云盘，避免单机故障同时损失数据库和备份。
- 来源部分失败时会在约 1 小时后重试，成功同步仍按主题原来的周期执行；部分失败不会被显示成“没有新论文”。
- 每条成功同步会把元数据放入本机库，已排除/已读论文仍会参与去重，避免下次以“新论文”再次进入收件箱。

## 长期研究 Agent

研究 Agent 面向“研究目标”运行，不是一次性搜索按钮。目标会保存核心问题、关注维度、排除条件、来源、产物和停止条件；专项研究运行生成可审阅的 DAG；自主 Agent 运行不预先生成固定步骤，而是在 LangGraph 中根据目标、内置记忆和工具结果动态决定下一步，可调用工具、反思或直接回答。两种入口都把输入和输出保存下来。证据综述再继续“全文准备 → 页级提取 → OCR 降级 → Claim → Evidence → Critic → 补证据 → 再核验 → 比较 → 补比较字段 → 重建最终矩阵 → 最终批判 → 研究产物”。每个步骤都记录输入/输出结构、完成条件、预算、耗时、错误和重试次数，刷新或重启后可以查看并继续。Apply/External 或全文页面外发步骤会在运行中停到等待确认；停止条件未满足时会在总预算内自动执行一次受限证据收敛轮次，仍有阻塞项会以“部分完成”状态展示。身份解析会明确标记 DOI、arXiv、题名匹配或未解决；引用扩展只产生候选快照，不会自动写入文献库，用户仍然逐篇选择导入。补充检索和引用扩展产生的临时候选会在全文准备、Claim、比较和最终产物阶段再次按稳定论文身份去重，避免同一工作被重复计数或重复推荐；多篇本地 PDF 提取使用有上限的并行工作线程，进度和输出顺序仍保持可追踪、可复现。

Agent 的阅读卡步骤会复用同一套持久化 AI 任务系统，而不是生成摘要占位文本：有本地 PDF 且模型配置可用时，任务会按页提取文字并生成带页码证据的结构化卡片与读前准备，不渲染或发送页面图像；公式、表格、曲线和流程图由多模态深度精读处理。任务 ID、阶段、进度、耗时、失败原因和重启中断状态会被保存。Agent 只生成 review-only 草稿，不覆盖人工阅读卡；无 PDF、未配置模型或任务失败时会明确返回缺口，不能被标记为“已精读”。

它的长期差异化在于三层记忆：目标论文历史记录首次发现、最近发现、出现次数、阅读状态和用户判断；版本关系识别 DOI、arXiv、题名/作者和年份对应的预印本、会议版、期刊版；证据记忆将摘要摘录与全文页码摘录分开，Claim 按研究问题、方法、数据集、结果和局限分类。比较矩阵发现方法、数据集或结果缺口时，Agent 会回到已有本地 PDF 页级文本补证据，保存连续原文、页码、章节和文本哈希；没有本地全文则明确标记缺口；Agent 只在你选择已导入候选并确认后下载公开 PDF，下载和模型外发是两次独立授权，不会自动把候选全部入库。`CriticAgent` 会持续列出反例、证据不足、样本偏差、实验设计风险和结论过度外推，不把摘要推断伪装成全文结论。

三类入口分别适合建立研究地图、做证据综述和多年追踪。追踪入口使用独立的 `FollowUpAgent` 比较目标论文历史，只报告稳定身份意义上的新增、元数据/版本变化，并把重复命中保留为审计信息；候选仍需你明确选择后才进入文献库。研究目标可设置周期自动运行；所有目标、运行、候选历史、Claim、Evidence、批判和产物都包含在 JSON 导出和 ZIP 备份中。证据综述还会在页文本提取后检查低质量/空白页面，并仅在可选 OCR 依赖可用时尝试最多 24 页；比较矩阵补回的页级 Claim 会被重新核验和批判，最终产物使用重建后的矩阵。依赖缺失、文件缺失或识别没有改善都会作为运行步骤状态显示，普通高质量文本页不会额外进入 OCR。

## 相关性与长期记忆

当前的相关性评分是本地可复现的分诊信号：查询词在标题中的命中权重最高，摘要/作者命中次之，再结合与现有馆藏主题词的重合；它不等同于论文质量、创新性或正确性。摘要缺失时会显示“待核验”。

在发现结果中可以点击“标记相关”或“忽略此主题”。判断保存在 `query_matches` 中，按主题独立记录，不会因为你忽略了一个主题而影响另一个主题。主页的“研究画像”还会综合已读、收藏、主题反馈和重复次数给出下一步推荐；推荐页的全局“不再推荐”写入 `learning_feedback`，不会误伤其他主题。论文详情可查看与各主题、馆藏论文的高相关/邻近方向/跨领域关系。OpenAlex 参考文献同步保存在 `citation_edges` 中；目前只保存来源 API 给出的参考文献 ID，不声称已经解析出 PDF 正文中的所有提及。

## 当前边界与后续顺序

1. 继续扩大学术来源覆盖，并为联邦检索与推荐质量建立 precision@k、source recall 等人工评测集；优先接入有稳定 API 的学术服务，沿用可替换的 Provider 接口。
